Ambiente React + Vite com Docker Compose no Ubuntu 26.04 e derivados

Configuração completa para executar os exemplos práticos sem instalar o Node.js no sistema hospedeiro.

Professor Lucas Bueno

Para executar os exemplos de React + Vite em um container no Ubuntu 26.04 e derivados mantendo o sistema hospedeiro limpo, a configuração do Docker Compose precisa resolver dois detalhes fundamentais:

1. Permissões de Usuário (UID 1000) Mapear o usuário local do Ubuntu (1000:1000) para evitar que os arquivos gerados pelo Vite fiquem bloqueados como root ao editar no VS Code.
2. Exposição de Rede (--host) Ativar a flag --host no servidor do Vite para expor a porta 5173 para fora do container e permitir o acesso pelo navegador local.
1

Estrutura de Diretórios e compose.yaml

Crie a pasta do projeto no Ubuntu antes de subir o container para garantir que o diretório meu-projeto pertença ao seu usuário local e não ao root do daemon do Docker:

</> Código na área Terminal (Bash) 
mkdir -p ~/dev-react/meu-projeto
cd ~/dev-react

Na pasta ~/dev-react (um nível acima de meu-projeto), crie o arquivo compose.yaml:

</> Código na área ~/dev-react/compose.yaml 
services:
  react-dev:
    image: node:22-alpine
    container_name: vite_react_dev
    # Mapeia o usuário padrão do Ubuntu (1000:1000) para evitar arquivos criados como root
    user: "1000:1000"
    working_dir: /app
    volumes:
      - ./meu-projeto:/app
    ports:
      - "5173:5173"
    # O '-- --host' instrui o Vite a escutar em 0.0.0.0 dentro do container
    command: npm run dev -- --host
    stdin_open: true
    tty: true
Por que deixar o compose.yaml um nível acima? Isso mantém a pasta meu-projeto limpa e idêntica à árvore de arquivos do material (public, src, .gitignore, eslint.config.js, index.html, package.json, README.md e vite.config.js), além de permitir que o comando de criação do Vite rode sem reclamar que a pasta não está vazia.
Por que usar -- --host? Por padrão, o npm run dev atrela o servidor apenas ao localhost (127.0.0.1) interno do container. Passar --host libera o acesso para o navegador do seu Ubuntu via http://localhost:5173/.
2

Criando o Projeto Vite pelo Container

Ainda dentro de ~/dev-react, utilize o docker compose run como demonstrado a seguir para executar os comandos de criação do projeto e instalação das dependências diretamente no container efêmero:

  • 01
    Gerar a estrutura do projeto React com Vite:
    </> Código na área
    docker compose run --rm react-dev npm create vite@latest . -- --template react

    Nota: usamos o ponto . no lugar de meu-projeto porque o diretório de trabalho /app do container já está mapeado diretamente dentro da pasta ./meu-projeto. Caso o assistente do Vite faça alguma pergunta interativa no terminal para iniciar o projeto ou serviço, selecione No, neste momento queremos apenas a criação dos arquivos.

  • 02
    Instalar as dependências iniciais (gerando a pasta node_modules):
    </> Código na área
    docker compose run --rm react-dev npm install

    Esse passo lê o package.json recém-criado e popula a pasta node_modules localmente com as permissões do seu usuário.

3

Executando a Aplicação e Editando no VS Code

Com o projeto instalado, inicie o ambiente e abra o editor no Ubuntu:

  • 01
    Suba o servidor de desenvolvimento em segundo plano:
    </> Código na área
    docker compose up -d
  • 02
    Acompanhe os logs (opcional) para ver a saída do Vite:
    </> Código na área
    docker compose logs -f

    Você verá a confirmação do servidor rodando e pronto para uso em http://localhost:5173/.

  • 03
    Abra a pasta do projeto no VS Code instalado no Ubuntu:
    </> Código na área
    code meu-projeto
Atualização em Tempo Real (HMR Nativo) Como o Docker no Linux utiliza o compartilhamento nativo de sistema de arquivos do kernel (inotify), o HMR (Hot Module Replacement) funciona instantaneamente: qualquer alteração salva pelo VS Code em src/App.jsx ou nos novos componentes (como src/componentes/PainelProduto/index.jsx) atualizará a página no navegador em tempo real.
4

Comandos do Dia a Dia para os Exercícios do Material

Sempre que o material pedir para executar um comando npm no terminal, basta dispará-lo através do container em execução (ou usando run --rm se o container estiver parado):

Tarefa no Material Comando Equivalente com Docker Compose
Iniciar o servidor (npm run dev) docker compose up -d
Parar o servidor docker compose down
Instalar o Axios (npm install axios) docker compose exec react-dev npm install axios
Recriar a node_modules em caso de problemas rm -rf meu-projeto/node_modules && docker compose run --rm react-dev npm install
Abrir um shell interativo dentro do container docker compose exec react-dev sh
